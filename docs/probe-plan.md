# これから踏む動作モードと、得られる可能性があるもの

**未同定の項目を「どの走行で埋まるか」で束ねた表。** 個々の根拠は
[`FINDINGS.md`](FINDINGS.md)、作業状況は [`../HANDOFF.md`](../HANDOFF.md)。

前提を 2 つ。**標準層（ELM327）と独自層（基板）はセッションとして排他**なので、
同じ走行で両方は読めない。**独自層の記録は基板に任せきりにできる**（IG ON で
`auto` が起動し、スマホは転送だけ）ので、走行そのものの負担はほぼ無い。

## A. 1 速全開でレブまで

**1 速 9,000rpm = 42 km/h。** 法定内で数秒。**これ 1 回で 5 つ埋まる。**

| 埋まるもの | 判定 |
|---|---|
| **噴射の `nQ`（噴射回数 × 流量）** | 定格点なので BSFC 300 g/kWh × 20 kW で燃料流量が既知になり、`nQ = 必要量 ÷ 有効パルス` が直に出る。**全開では無効噴射時間がパルスの 1 割しか効かない**ので、その不確かさに強い |
| **噴射回数（1 回転 1 回 か 1 サイクル 1 回）** | 9,000rpm で **counts > 1707（= 6.67 ms）なら 1 回転 1 噴射は物理的に不可能**。それ以下なら未決のまま |
| **`[7]` のスケールと一次性** | `[6]` が 225 付近に達したときの `[7]`。`[7] = 0.770 × [6] − 20.08` の外挿が成り立つか、折れ点があるか |
| **`0xD1` index 5 / 6 / 7** | 回転数の上 37%（6,628 → 10,500rpm）は未踏。動くか |
| **`0xD1` index 8 の bit 2** | 停車では 2,500rpm のしきい値に見えたが走行で崩れた。高回転側を足す |

**記録**：`poll D1 11`。全開に入る直前に `note` を打つ。

**外れたら**：`nQ` は E（満タン回帰）へ。`[7]` は折れ点の位置を別に探す。

## B. 朝一の冷間始動を記録

**記録するだけ。** 独自層のログは水温 33℃ が下限で、**真の冷間始動が 1 度も無い**。

| 埋まるもの | 判定 |
|---|---|
| 暖機補正 `[21]` / `[22-23]` の低水温端 | 現状 34℃ で 7,579。外気温付近まで延ばすと形が見える。目標アイドル回転数説の検証 |
| `0xD1` index 5 / 6 / 7 | 冷間で動くか |
| `0x61` が冷間でも凍結しているか | 25 分・暖機をまたいで全バイト同一だったが、**始動時に書かれて以後固定**なら冷間始動時だけ違う値が入る |
| 冷間のオープンループが独自層に出るか | 標準層は 42℃ が境界と同定済み。独自層側に対応する旗があるか |

**記録**：`auto` に任せる。IG ON から始動までを含める。

## ~~C. 停車 1 分の状態試験~~ → 不要になった

`0xD1` index 9 は**ラジエータファン**と同定できた（入 100℃ / 切 98℃）。既存の
ログだけで決着したので、この試験は要らない。詳細は
[`FINDINGS.md`](FINDINGS.md)。

**決め手は「停車探索の後半でラジエータファンが回っていた」という現場の記憶。**
それを手掛かりに ECT と電圧を当てたら一発で合った。**ログに写っていない事象の
記憶は、解析の入力になる。** 走行のたびに気づいたことを `note` に残す価値がある。

## D. 長い惰行

**60 km/h 以上からクラッチを切ったまま 30 km/h 台まで、数十秒。** 勾配の小さい道を
**往復**して勾配を相殺する。

| 埋まるもの | 判定 |
|---|---|
| **走行抵抗 CdA / Crr** | 噴射 = 0 かつ駆動フラグで、惰行を 2 種類に分けられる。クラッチ切り＝空気＋転がり、ギヤ繋ぎの燃料カット＝＋エンジンブレーキ。速度の減衰に `a = −(½ρ·CdA·v² + Crr·mg)/m` を当てれば `v²` 項と定数項として分離する |

**これは [`GEARING.md`](GEARING.md) の穴を直接埋める。** あちらは CdA = 0.60 m² /
Crr = 0.020 を**仮定値**で置いており、実測で検証していないと明記してある。

**既存のログでは足りない。** 燃料カットは 167 サンプル入っているが市街地で減速区間が
短く、しかも 3 本とも 3,800〜5,400rpm の低い段でエンジンブレーキが支配していて
`v²` が見えていない。**クラッチを切った惰行が 1 本も無い。**

## E. 満タン区間の記録

**普段の給油を記録するだけ。** モデルが線形なので合わせ込みが要らない。

```
燃料[cc] = a·S − b·N       S = Σ(counts/256 × サイクル数)、N = Σサイクル数
                            a = nQ/60000、b = a × 無効噴射時間
```

給油区間ごとに 1 本の式が立つ。**街乗り中心の区間と流し中心の区間で `S/N` 比が
変わるので、区間を数本ためれば `nQ` と無効噴射時間が同時に決まる。**

満タン位置の再現性（±50 mL）は 1 区間 6〜10 L に対して 1% 未満。**区間あたりの
誤差であって L あたりではない**ので、区間を長く取るほど効かなくなる。

**運用**：給油のたびに、その区間のログファイル名と給油量を控える。

## F. `0x20` / `0xD0` の専用ポーリング

**`poll D0 20 11 D1` で 4 本同時。** アンカーを外すと意味が読めないので必ず載せる。

**載せてもコストはゼロ。** 応答するテーブル 1 本のコストは **37ms**（走行中の実測、
n=2,658 と n=5,498 で一致）。周期 200ms に対して **5 本まで 5.0Hz を維持できる。**

| テーブル数 | 作業 | 周期 | 各テーブル |
|---:|---:|---:|---|
| 2（現行 `D1 11`） | 80ms | 200ms | **5.00 Hz** |
| **4（`D0 20 11 D1`）** | **160ms** | **200ms** | **5.00 Hz** |
| 5 | 200ms | 200ms | 5.00 Hz（限界） |
| 6 | 240ms | 240ms | 4.17 Hz |

停車の実測でも `00 20 61 70 D0` の 5 本同時で各 5.0Hz が出ている。**枠が 1 本余るので、
`0x61` を足して「凍結が全条件で成り立つか」も同時に見られる。**

**手元のデータでは解けないことを確認済み。** 231 フレームあるが **229 が停車探索**
（`probe.bin`）由来で、走行中は各 1 フレームしかない。既知信号（rpm・ECT・IAT・
MAP・電圧・噴射・車速）との相関は**全部 |r| < 0.35**。速度も負荷も振れていないので
当然で、**走らせないと分からない。**

**先行事例にはフレームがあり、意味は無い。** ただし比較材料にはなる。重要なのは
**上流の CRF ダンプがエンジン停止で取られている**こと（同じダンプ集の `0x11` で
rpm が `00 00`）。**あそこのゼロは「未使用」ではなく「動いていない」。**

| | MC52（運転中 231 フレーム） | CRF250L（停止時 1 発） |
|---|---|---|
| `0x20` `[4]` | `28`–`2B` を漂う（5 種） | `FF` |
| `0x20` `[5]` | **`80` 定数** | **`80`** ← 一致 |
| `0x20` `[6]` | ほぼ `01`（2 種） | `00` |
| `0xD0` `[4]` | **`83` 定数** | `81` ← 定数同士。ID らしい |
| `0xD0` `[5]`–`[14]` | 全部 `00` | `00` |
| `0xD0` `[15]` `[16]` `[17]` | **動く**（`[15-16]` 470–532、`[17]` 174–198） | `00 00 6B` |
| `0xD0` `[18]`–`[23]` | 全部 `00` | `00` |
| `0xD0` `[24]` | 68–73（6 種） | `FE` |

**狙いは速度・負荷を広く振ること。** 停車では動かないバイトが動くかを見る。

## G. キルスイッチで停止

**1 回やるだけ。** これまでキーオフしか踏んでいない。停止経路が違えば
`0xD1` の状態バイトに差が出る可能性がある。

## H. 高速道路（法定内）

独自層は 66 km/h 止まり。6 速の常用域と高速側の定常点が取れる。
[`GEARING.md`](GEARING.md) の突合を高速側へ延ばせる（現状 110 km/h まで、
ただし**標準層のログでの話**）。**公開する図の車速上限は 120 km/h**
（`SPD_MAX_PUB`）。

## I. サービス `21` / `1A` / `23` / `30` の総当たり

**当初の動機は消えたが、別の動機が残っている。** 「標準層で他に何か取れないか」は
独自層が埋めた。残るのはこれ。

**`index.html`（公開している Web アプリ）はセッション排他のせいで駆動フラグが
永久に来ない。** もしサービス `21`（readDataByLocalIdentifier）が標準セッション内で
拡張データを返すなら、**基板なしのスマホだけで駆動状態ゲートが使える。**
公開物の価値に直結する唯一の経路。

**確率は低い。** Honda は独自層を別プロトコルで実装しているので、`21` も実装して
いる理由は薄い。ただし**数分**で済み、**基板の `X`（生送信）でウェイクアップ前に
叩ける**ので ELM327 を別に繋ぐ必要も無い（標準層と独自層は排他だが、`w` の前なら
標準層が通る）。

副次的に「否定を確定できているのはサービス 22 だけ」という穴も塞がる。

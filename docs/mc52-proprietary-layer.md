# Honda CB250R（2BK-MC52）メーカー独自層の同定

### — K-Line 上の規格外プロトコルと、比推定の真値評価 —

**Author:** k4n4（mc52obd Project）
**Version:** 1.0（2026-09）

**前編:** [`mc52-standard-layer.md`](mc52-standard-layer.md)

---

## Abstract

本レポートは、Honda CB250R（2018年式、2BK-MC52）の ECU が K-Line 上に持つ
メーカー独自のプロトコルを同定し、そこから得た信号で前編の推定則を評価した記録で
ある。

前編は、標準 OBD 層で取得できる範囲を全数探索により確定し、そこに 3 つの量——
ギヤ段・燃料消費量・クラッチの断続——が存在しないことを示した。またギヤ段の比推定を
定式化し、確定率 98.1% を得た一方で、クラッチを切った状態を原理的に区別できないこと、
およびその誤判定を機械的に計数する手段も無いことを示した。

本レポートはその 3 つの欠落を目的として開く。同じ 4 ピンカプラ・同じ K 線の上に、
標準層とは別のプロトコルが存在する。**規格と一致するのは物理層だけ**で、フレーム
構造・チェックサム規則・セッションの張り方・サービス番号体系のいずれも規格外である。
したがって市販のドングルでは到達できず、K 線を直接駆動する基板を設計・製造した。

テーブル総当たり 256 本のうち実在するのは 7 本であった。`0x11` が 25 バイトの
センサ群で、その中に**噴射時間**がある。標準層の `5E`・`2F` はいずれも非対応で
あるから、燃料に関する量はここにしか無い。`0xD1` は状態フラグ群で、index 4 が
**駆動の断続**を、index 9 が**ラジエータファン**を示す。**ギヤ段そのものを示す
フィールドは、実在する 7 本のいずれにも無かった。**

駆動の断続は、前編の比推定に対する**正解ラベル**として機能する。これにより誤判定の
計数が機械化され、判定則を過学習の疑いなく評価できるようになった。誤答率は走行内容
によって 4.2%〜12.1% と 3 倍動く。率そのものは指標にならず、生成機構で語るべきで
あることを示す。

## Key Findings

- 独自層が規格と一致するのは **OSI 第 1 層（K 線・10,400bps・8N1）だけ**である。
  第 2 層以上——フレーム構造・チェックサム・セッション・サービス番号——はすべて規格外。
- 実在するテーブルは **7 本**（`00` `11` `20` `61` `70` `D0` `D1`）。256 本の総当たりで
  残り 249 本は長さ 5 の空応答を返す。応答チェックサムは**総和の 2 の補数**で、
  走査した 256 フレームすべてで一致した。
- **keep-alive は不要。** 60 秒の無通信を挟んでもテーブルが読める。
- `0x11` のアナログセンサは**「生の A/D 値 ＋ 換算済みの値」の対**で並ぶ。
  MAP は `[13] = 0.716 × [12] − 5.25`、r = +0.9999、残差 SD 0.36 kPa。
- **噴射時間**を同定した（`[18-19]`、16bit BE）。標準層に対応する量が無い。
  LSB は最小指令パルスとアイドル幅から **`1/256 ms`** と推定した。
- `0xD1` index 4 が**駆動の断続**（`00` 駆動／`01` N かクラッチ切り／`03` サイド
  スタンド）を示す。**前編が原理的に解けないとした領域を、この 1 バイトが分ける。**
- `0xD1` index 9 は**ラジエータファン**（入 100℃ / 切 98℃）。走行中は水温が 96℃
  止まりで一度も立たない。
- **ギヤ段フィールドは存在しない。** 停車 750 サンプルと走行 3,837 サンプルで確認した。
  市販シフトインジケータが取り付け時に学習を要求する事実と整合する。
- 独自層の車速バイト `[17]` は標準層 `0D` と**同じ信号**であり、前編の校正をそのまま
  継承できる。
- 駆動フラグを真値として用いると、誤答率は走行 3 本で **4.2% / 6.8% / 12.1%** と
  3 倍動く。**率を精度として扱ってはならない。**
- 駆動フラグを判定に用いると、駆動中に段が付いた割合が 87〜96% → **99% 台**、
  駆動していないのに段を答えた行が **0** になる。ただし標準層と独自層はセッションと
  して排他であり、ELM327 経路にこのフラグは来ない。

## 1. はじめに

### 1.1 どこまでが規格で、どこからが独自か

同じ 4 ピンカプラ・同じ K 線の上に、標準層とは別のプロトコルが載っている。
「メーカー独自」という語は曖昧なので、階層で切り分ける。

**表1. 規格との対応**

| OSI | 規格（標準層） | 独自層 | |
|---|---|---|---|
| **7** アプリケーション | SAE J1979 サービス`01`（PID）／ KWP2000 サービス | コマンド `0x71` ＝ テーブル読み。**J1979 にも KWP にも無い番号** | 非準拠 |
| **5–6** セッション | 診断では実質不在 | **独自のウェイクアップでセッションを張る。標準層と排他** | 規格外 |
| **3–4** ネットワーク / トランスポート | ISO 14230-2 のアドレッシング（K-Line は長さバイトで足りるので分割は無い） | **アドレスの概念が無い。**長さバイトのみ | 非準拠 |
| **2** データリンク | ISO 14230-2：形式バイト・宛先／送信元・**単純和**・P1〜P4 | `[固定バイト][長さ][コマンド][引数][CS]`・**総和の 2 の補数** | 非準拠 |
| **1** 物理 | ISO 14230-1：K 線・12V オープンドレイン・**10,400bps・8N1** | **同一** | **準拠** |

**共有しているのは第 1 層だけである。**

ウェイクアップについては「同じ手口・別パラメータ」と言える。ISO 14230 の fast init は
25ms Low / 25ms High、独自層は **70ms のブレーク**＋独自のバイト列で、長い Low で
起こすという発想は共通だが互換性は無い。第 1 層と第 2 層の境目にあたる。

**第 1 層の一致は主張ではなく観測である。** 本レポートで用いた基板は、UART の設定を
一切変えずに両層を叩いている。変わるのは送るバイト列だけである。

### 1.2 この 1 行から 3 つが導かれる

**同じ線・同じトランシーバ・同じ UART 設定で両層に届く。** 第 1 層が同じだからで
あり、1 台の装置で両方を扱える理由でもある。

**市販のドングルでは 1 バイトも読めない。** 第 2 層から上が別物だからである。ELM327 は
OBD2 の通訳として作られており、ブレーク長を指定するコマンドも、異なるチェックサム
規則も、「テーブルを読む」という概念も持たない。ドングルの制約ではなく規格の外にある。

**両層は排他である。** 線が 1 本でセッションが 1 つだからである。標準層を読んでいる
間は独自層を読めず、逆も同じ。

### 1.3 目的

前編は標準層に存在しないものを 3 つ挙げた。本レポートはそれを目的として開く。

| | 前編での状態 | 本レポートでの扱い |
|---|---|---|
| クラッチの断続 | 無い。**比推定が原理的に解けない原因** | §4.4 |
| 燃料消費量 | `5E`・`2F` とも非対応 | §4.3 |
| ギヤ段 | 標準 OBD に定義が無い | §4.6（**存在しなかった**） |

加えて、前編は「誤判定を機械的に計数できない」とも述べた。駆動の断続が取れれば
それが正解ラベルになる。§6 がその評価にあたる。

## 2. 解析対象

### 2.1 到達手段

K 線を直接駆動する基板を設計・製造した。構成を Fig1 に示す。

![Fig1](figB-block.svg)

**Fig1. 基板のブロック図。** 車両の 4 ピンカプラから 12V と K-Line を受け、`D1`
（逆接保護）を通した `VIN` から `U1`（降圧）で 3.3V を作る。`U3`（L9637D）が
12V 単線と 3.3V ロジックの間を仲介し、`U2`（ESP32-S3）が UART で叩く。
`R7`（510Ω）は K 線のプルアップである。

**表2. 取得の条件**

| | |
|---|---|
| 1 テーブルの往復 | **37ms**（走行 2 本で実測、n=2,658 / n=5,498 とも中央 37ms） |
| ポーリング周期 | 200ms。**5 本まで各 5.0Hz を維持できる** |
| 本レポートの主データ | `poll D1 11` の 2 本、**各 5.0Hz** |
| 記録形式 | **生フレームの追記** |

**生フレームで記録する。** 標準層と違い換算が未知であるから、解釈して書くと解釈が
誤っていたと判明した時点で過去のログが無価値になる。記録点は送受信の唯一の通り道に
1 箇所だけ置き、要求も応答も自動的に残る。

**無応答のテーブルは待ち 200ms を使い切る**ため、存在しないテーブルを 1 本混ぜる
だけで周期を捨てる。総当たりで実在を確かめてから周期読みに渡す。

#### 装置が嘘をついていないことの確認

未知の層へ入る前に、2 つの足場を置いた。

**車両に挿さずに通信経路を検証できる。** 基板に `R7` が載っているため、カプラを
車両へ接続しなければ K 線は開放端となり、`VIN` に 12V を与えると K は 12V に吊られる。
この状態で TX を Low にすれば L9637D が K を引き下げ、RX に返る。**TX → K → RX が
基板内で閉じる**ので、配線の入れ違いや短絡を車両へ行く前に切り分けられる。10,400bps で
1,024 バイト誤り 0 を確認した。

**車両では標準層を先に読んだ。** 前編で対応 PID も期待値も確定しているため、一致すれば
ファームウェアの土台が正しいと言える。**これにより、以降に観測される不一致を
「ファームウェアの不具合」ではなく「車両側の未知」として扱えるようになる。** 足場を
持たずに未知の層へ入ると、どちらの問題かを判定できない。

### 2.2 取得データ

**独自層のログ**：`0xD1` と `0x11` を交互に周期読みし、生フレームを内蔵フラッシュへ
追記した。実走 3 本（8.9 分 / 4.0 分 / 18.4 分）、テーブルあたり 5.0Hz。停車での探索
1 本（25 分）とギヤ掃引 1 本を加え、`0xD1` は合計 11,135 フレーム、`0x11` は
10,384 フレームを得た。

**GPS**：スマートフォンの Geolocation を端末時計で記録した。基板の時計は接続時に
ページが設定するため、両者は同一時間軸に乗る。

**前編の成果を参照定数として使う。** 車速の切り捨て補正（+0.5）、ギヤ判定の係数
`k` = 1.0057、判定窓の構成、諸元（減速比・タイヤ周長）はいずれも前編で確定したもので、
本レポートでは再導出しない。

## 3. 解析手法

**総当たり**：テーブル番号を全域にわたって要求する。目的は実在するものの列挙と、
**存在しないことの確定**である。

**操作対応**：独自層のバイトは既知の参照信号との相関が取れない場合がある。その場合は
**操作と変化の対応**で同定する。スロットルを煽る、クラッチを切る、ギヤを入れると
いった操作を時刻とともに記録し、同期して動くバイトを探す。この目的のため、
スナップショットではなく周期読みの時系列を取る。

**構造の判別**：隣接バイトの**相互相関**と**桁上がりの回数**を数えると、16bit 値と
「生 A/D 値 ＋ 換算値」の対を機械的に分けられる（§4.2）。

**真値ラベルによる評価**：推定則の誤りを数えるには、推定と独立な正解が要る。§6 では
`0xD1` の駆動フラグを正解ラベルとして用いる。

**同定・推定の区別**：実測で一意に決まったものを「同定」、複数の観測から矛盾なく
説明できるが一意でないものを「推定」と書き分ける。

## 4. 解析結果

### 4.1 ウェイクアップとテーブル構成

ウェイクアップは 2 種類を順に試し、**`FE 04 72 8C`** で通った。**独自層は IG ON
（エンジン停止）でも応答する。**

`0x00`〜`0xFF` の 256 本を走査した結果を Fig2 に示す。

![Fig2](figA-tables.svg)

**Fig2. テーブル総当たりの結果。** 応答したのは 7 本のみで、緑のセルに応答長を
付した。残り 249 本は長さ 5（`02 05 71 TT CS`、中身なし）を返す。

**応答チェックサムは総和の 2 の補数であり、走査した 256 フレームすべてで一致した
（256/256）。**

**表3. 実在するテーブル**

| | 長さ | 内容 |
|---|---:|---|
| `00` | 15 | keep-alive に使われる静的データ |
| **`11`** | 25 | **センサ群**（§4.2） |
| `20` | 8 | `[4]` が `0x28`〜`0x2B` をゆっくり漂う。**未同定** |
| `61` | 25 | **凍結データ。** 25 分・暖機の進行をまたいで 152 サンプル全バイト同一 |
| `70` | 8 | 完全に静的 |
| `D0` | 26 | `[15-16]` と `[17]` が動く。**未同定** |
| **`D1`** | 11 | **状態フラグ群**（§4.4、§4.5） |

**`0x61` に `0x11` の配置を当ててはならない。** 長さが同じ 25 バイトであるため当てたく
なるが、凍結データであり生きていない。当てると回転数 0 / 電圧 1.5V / 車速 5km/h という
値が出る。

手順に関する実測を 2 点記す。

- **keep-alive は不要である。** 5 / 10 / 20 / 40 / 60 秒の無通信を挟んでも 5 回すべて
  テーブルを読めた（60 秒を超えるタイムアウトは未測定）。
- **ウェイクアップは電源投入後に必須である。** 実行前のテーブル読みは `FF` を 1 バイト
  返すのみである。

### 4.2 `0x11` のバイト構造

隣接する全バイトについて相互相関と桁上がりの回数を数えると、構造が機械的に分かれる。

**表4. `0x11` の構造**

| バイト | 相互相関 | 桁上がり | 構造 |
|---|---:|---:|---|
| `4-5` | −0.004 | **294** | **16bit BE** —— 回転数 |
| `6-7` | **+0.999** | 0 | **対** —— `[6]` 生 A/D、`[7]` 派生 |
| `8-9` | −0.982 | 0 | **対** —— 冷却水温 |
| `10-11` | −0.994 | 0 | **対** —— 吸気温 |
| `12-13` | **+0.9999** | 0 | **対** —— 吸気管絶対圧 |
| `14` `15` | — | — | 常に `FF`。未使用 |
| `16` | — | — | 単独。電圧 |
| `17` | — | — | 単独。車速 |
| `18-19` | +0.004 | **201** | **16bit BE** —— 噴射時間 |
| `20` | — | — | 単独。点火進角 |
| `21` | +0.991（対 `22`） | — | `22-23` の粗い版 |
| `22-23` | +0.006 | **460** | **16bit BE** —— 暖機補正らしき量 |

**アナログセンサは「生の A/D 値 ＋ 換算済みの値」の対で並ぶ。** 前半に `× 5 / 256` を
掛けるとセンサ電圧になる。MAP で検証すると `[13] = 0.716 × [12] − 5.25`、
**r = +0.9999、残差 SD 0.36 kPa**。冷却水温と吸気温は NTC サーミスタの形（冷で高電圧、
熱で低電圧）を示す。**`[12]` は `[13]` より分解能が高い**（0.72 kPa/count 対
1 kPa/count）。

**`18-19` は対ではない。** センサ対の形（r ≒ ±0.99）に見えるかを確かめたが **r = +0.004**
で、代わりに桁上がりが 201 件出た。

```
3.  9 =  777  →  2.231 =  743    16bit 差 −34
1.235 =  491  →  2.  4 =  516    16bit 差 +25
```

下位が 222 飛んでいるのに値は 25 しか動いていない。**繰り上がりであって物理量の変化
ではない。** 16bit BE で読んだときだけ隣接変化が滑らかになる（中央値 9）。

**対になっているのはアナログセンサだけである。** 生の A/D 値が存在するから両方を報告
できる。噴射時間は ECU が計算して出す指令値なので、対応する生 A/D が存在しない。
**構造が意味を教えている。**

標準層と同じ符号化を持つものが 2 つある。`[6]` を `A × 100/255` として換算すると
アイドルで 10.2% となり、標準層 PID `11` と小数第 1 位まで一致する。`[20]` は
`A/2 − 64` で読むとアイドルで 9.5° となり、標準層 `0E` と一致する。

### 4.3 噴射時間

`0x11` のセンサ群の中に、標準層には存在しない量がある。

![Fig3](figC-injection.svg)

**Fig3. 噴射時間の時系列。** 左は停車・空吹かし、右は走行・減速。アイドルで 611〜648 に
安定し、スロットルを開けた瞬間に 801 まで跳ね、閉じた瞬間に 370 へ落ちる。走行中の
減速では **0** になる（燃料カット）。

**この量は独自層にしか無い。** 前編で標準層の `5E`（燃料流量）と `2F`（燃料残量）が
いずれも非対応であることを確認済みである。

走行 2 本での範囲は 0〜1,546、バイトオーダは BE である。**カット中の 150/167 サンプルが
「駆動が繋がっている」状態**であり（残り 17 件はカット中にクラッチを切った遷移）、
エンジンブレーキ中の挙動と整合する。

**LSB は `1/256 ms` と推定した。** 給油との突合を用いず、離散候補への総当たりで決めた。

実測 2 点を使う。**最小指令パルスは 350 counts**（燃料カット明けの復帰値 100 件が
349〜360 に密集。それ未満は単発で、5Hz で変化の途中を拾った過渡）、**アイドルは
618 counts**（暖機後、n=4,218）。LSB はタイマのティックなので候補は離散であり、
次の 2 条件で落とす。**どちらも燃費・流量・噴射回数を使わない。**

- 最小指令パルスが無効噴射時間（0.6〜1.0 ms）を上回り、かつ最小指令として常識的な
  範囲（〜2 ms）に入ること
- アイドルが 250cc 単気筒のアイドルとして妥当な幅（1.4〜4.5 ms）に入ること

| LSB | 最小パルス | アイドル | 判定 |
|---|---|---|---|
| 1 µs | 0.35 ms | 0.62 ms | ✕ 無効噴射時間より短い |
| 2 µs / `1/512 ms` | 0.70 ms | 1.24 ms | ✕ 同上、アイドルも狭い |
| **`1/256 ms`（3.906 µs）** | **1.37 ms** | **2.41 ms** | **○** |
| 4 µs | 1.40 ms | 2.47 ms | ○（`1/256 ms` と 2.4% 差で区別不能） |
| 5 µs | 1.75 ms | 3.09 ms | ○ |
| `1/128 ms` 以上 | 2.73 ms〜 | 4.83 ms〜 | ✕ 最小指令が長すぎる |

残る 3.9〜5 µs のうち、**設計上の必然性があるのは `1/256 ms` だけ**である。8.8 固定
小数点の ms として読むと**上位バイトがそのまま整数 ms** になり、その分布が物理的に
素直になる（2 ms にアイドルが集中し、1 ms が最小指令、負荷で 3〜5 ms、6〜7 ms は
9 件のみ）。刻みは 1 count で mod 2〜256 のすべての剰余が出るため、**報告値が内部
分解能そのもの**であることも確認した。

**これは推定であり同定ではない。** 前提として効いているのは**無効噴射時間 0.6〜1.0 ms**
と**最小指令パルスの上限 2 ms** の 2 つで、後者を 2.8 ms まで許すと `1/128 ms` が
復活する。

**燃料の絶対量にはさらに `噴射回数 × インジェクタ流量` が要る。** アイドル消費と実走
燃費の妥当域から `nQ` ≈ 220〜330 cc/min まで挟めるが、±20% であり勘定には足りない。
定格点（1 速全開）での測定と、満タン区間の回帰で決まる（§8）。

### 4.4 `0xD1` の駆動状態

停車で状態を 1 つずつ作り、各 15 秒（76 サンプル）ずつ記録した。

**表5. 停車での状態別の値**

| 状態 | index4 | index8 | index9 |
|---|---|---|---|
| A スタンド出す・N・クラッチ離す | `03` | `01` | `00` |
| B スタンド払う・N・クラッチ離す | `01` | `01` | `00` |
| C スタンド払う・N・クラッチ握る | `01` | `01` | `00` |
| D スタンド払う・1速・クラッチ握る | `01` | `01` | `01` |
| ギヤ掃引（エンジン停止、車体を転がしてシフト） | `01` と **`00`** が交互 | `00` | `00` |

**index 4 は駆動が繋がっているかを示す。**

| 値 | 意味 |
|---|---|
| `00` | 繋がっている（ギヤが入り、クラッチも繋がっている） |
| `01` | 繋がっていない（N **または** クラッチを切っている） |
| `03` | サイドスタンドが出ている |

**この 1 バイトが前編の限界を解く。** 減速中のクラッチ切りは `01`、本物の 6速は `00`
であり、比が数値的に同一であっても分離できる。

**index 8 はビットフィールドである。** bit 2 と bit 3 はいずれもスロットルに従う。
単一変数のしきい値で分離能を測ると、bit 2 はスロットル生 `[6] ≥ 29` で 93.4%
（全閉は 26）、bit 3 は `[6] ≥ 29` かつ車速 ≥ 20 で 94.9%。回転数を揃えて比べると、
どの帯でも bit 3 = 1 の側がスロットル・噴射・MAP のすべてで高い（3,500–4,000rpm で
スロットル 27 → 36、噴射 405 → 616、MAP 47 → 70）。**93〜95% なので推定である。**

**index 5・6・7 は 11,135 フレームで 1 度も動かない。** ただし**これを「未使用」と
読んではいけない。** 言えるのは「作れた状態の範囲では動かなかった」だけで、動かす
事象に出会っていない可能性が残る。踏めていない領域は明確で、回転数はレブリミット
10,500 に対し 6,628rpm 止まり、スロットルは生 111（標準層では 225 まで到達）、
水温は最低 33℃ で真の冷間始動が無い。

#### 状態設計の欠陥により一度誤結論した

A〜D を測った時点で、筆者は「index 4 はサイドスタンドのみを示し、クラッチは `0xD1` に
無い。したがって誤判定は除去できない」と結論した。**誤りであった。**

原因は状態 D を**クラッチを握った状態**で作ったことである。index 4 の定義からすれば
D で `01` が出るのは正しい挙動であり、足りていなかったのは「ギヤが入って、かつ
クラッチが繋がっている」状態である。それが停車では作れないと自身で記述しておきながら、
その穴を埋めずに棄却へ進んだ。**エンジンを切って車体を手で転がせば作れた**（index 4 =
`00` が 0.2〜0.8 秒のバーストで 10 回現れた）。

> **「その状態は作れない」と判断した時点で、棄却の結論は出せない。**
> 作れない状態が真偽を決めるなら、作る方法を先に考える。

### 4.5 `0xD1` index 9 はラジエータファン

`01` は 38 件あり、すべて停車・アイドルで観測された。水温で完全に説明がつく。

| ECT | サンプル | `index9 = 01` |
|---|---:|---|
| ≤ 97℃ | 10,304 | **0 件（0%）** |
| 99℃ | 50 | 13 件（26%） |
| **100℃** | 14 | **14 件（100%）** |
| **101℃** | 9 | **9 件（100%）** |

**入 100℃ / 切 98℃、99℃ は履歴依存。** ヒステリシス付きのサーモスイッチである。

```
830.5s  ECT  97  14.10V  i9=0
890.4s  ECT 101  13.90V  i9=1   ← 立つ（ECT ピーク）
895.0s  ECT  99  13.80V  i9=1
898.0s  ECT  97  14.40V  i9=0   ← 落ちる
```

**電圧が作動中に 13.80V まで沈み、切れた直後に 14.40V へ跳ねる。** 負荷の入切と
一致する。**走行 3 本で一度も立たないのは、走行風により最高でも 96℃ までしか
上がらないため**である。

当初これを「8.1 秒で落ちるラッチ」と読んだ。立った窓がたまたま停車状態試験の
state D と重なったためである。**そのとき index 4・index 8・回転数・スロットル・
噴射は比べたが、水温と電圧を見ていなかった。**

> **状態バイトが動いたら、状態バイトの中だけで説明を探さない。**
> そのとき車両に何が起きていたかは、アナログ側に出ている。

### 4.6 ギヤ段フィールドは存在しない

段数そのものを示すフィールドを探した。候補は `0xD1` の index 9 であったが、
**停車のギヤ掃引 750 サンプル、および走行 2 本 3,837 サンプルですべて `00`** であった
（§4.5 のとおり、その正体はラジエータファンである）。走行中はエンジンが運転しており
全段を使っているから、段数フィールドであれば値が動く。

実在する 7 本のテーブルに、段数らしい値を取るバイトは無い。**MC52 の ECU はギヤ段を
診断層へ出していない**と結論する。

この結論は、市販のシフトインジケータが取り付け時に学習を要求する事実と整合する。
あちらも段数を読んでいるのではなく、前編と同じ比推定を行っていると考えられる。

### 4.7 車速バイトは標準層と同じ信号

`0x11` の `[17]` を GPS と突き合わせた結果を Fig4 に示す。

![Fig4](figH-speed.svg)

**Fig4. 車速バイトと GPS。** GPS 精度 15m 以内・両方 5km/h 以上、GPS 側は絶対時刻で
線形補間。n = 1,345。青線は丁数比 14/15 = 0.9333。

比は 30km/h 以上で中央 0.939、全体の中央で 0.9346 であり、前編で確定した `0D`/GPS の
0.933〜0.942 と同じ範囲に入る。**別の信号ではない。** したがって前編の校正——切り捨て
なので真値は +0.5、ファイナルより上流、メーター誤差 +7.1%——がそのまま継承できる。
独自層のために校正をやり直す必要は無い。

30km/h 未満の帯で比が低く出て順序も崩れるのは、`0D` の 1 km/h 量子化と GPS 側の雑音に
よる。**切片つきの最小二乗はこの突合に使わない。** 切片が 20km/h 未満の GPS 雑音に
引かれ、実体のない値を返すためである（実測で `0.8974 × GPS + 1.252`）。帯ごとの
中央比で評価する。

## 6. 真値による判定則の評価

`0xD1` の index 4 は、前編の比推定と独立に得られる正解ラベルである。これにより、
判定則の誤りを**手作業のラベル付けなしに**計数できる。実走 3 本（合計 9,330 行）で
評価した。

### 6.1 駆動状態は比のクラスタの質を分ける

![Fig5](fig6-drive.svg)

**Fig5. 駆動状態で分けた比の散布。** 横軸は車速、縦軸は比（回転数 ÷ 車速）。比は段ごとに
定数であるから、理論値は水平な 6 本の線になる。左（駆動が繋がっている）は点が 6 本の線に
張り付き、右（N かクラッチ切り）は線と無関係に散る。

左の 1速の帯が線より上へ外れるのは、発進時の半クラッチである。滑るクラッチはエンジンを
駆動系より速くする方向にしか働かないため、必ず 1速の上側に出る。

### 6.2 比が解けない帯で、ラベルの質が反転する

![Fig6](fig7-band.svg)

**Fig6. 比が原理的に解けない帯。** 車速 20〜40km/h・回転数 1,700〜2,400rpm を拡大した。
●（駆動）は 75 点のうち 62 点が 6速の線に集まり一貫する。✕（非伝達）は 18 点が
3/4/5/6速に散り、意味を持たない。**同じ帯・同じ点で答えの質が反転する。**

### 6.3 誤答率は走行内容で 3 倍動く

「確定」と答えた行のうち、真値が非伝達であったものを誤答と定義して計数した。

**表6. 走行別の誤答率**

| 走行 | 行数 | 確定 | 誤答 | 率 |
|---|---:|---:|---:|---:|
| 1 本目（市街地中心） | 2,651 | 1,083 | 74 | **6.8%** |
| 2 本目（回転を合わせたシフトダウンを多く含む） | 1,186 | 486 | 59 | **12.1%** |
| 3 本目（通勤経路） | 5,493 | 2,997 | 125 | **4.2%** |

**この率を精度として扱ってはならない。** 3 本で 3 倍動いており、値を決めているのは
判定則ではなく走行内容である。**率ではなく生成機構で語る。**

### 6.4 誤答の生成機構

![Fig7](fig8-tolerance.svg)

**Fig7. 許容の内訳と誤答。** 1速と判定した点の上側のみを示す。1速の上側は隣の段が
無いため窓は設定値 4.0% 固定であり、そこへ量子化の不確かさ `0.5 / 車速` が素で足される。
8 km/h では 5.9% となり、合計 9.9% まで許す。

低速側の誤答は、この許容の内側に収まっている。**規則の例外ではなく、規則が通している。**

さらに重要なのは、**正答（灰）と誤答（赤）が同じ領域を占める**ことである。窓を狭めれば
本物の低速段を落とす。量子化の項は原理的に正しく——車速が 1 km/h 刻みである以上、
低速ほど相対誤差が大きいのは事実である——外すこともできない。**正しい項が、正しい理由で、
低速域を通しすぎている。**

高い段では別の機構が働く。2 本目の誤答 59 件は 1速12 / 2速17 / 3速11 / 4速11 / 5速4 /
6速4 に分布し、回転数 2,700〜3,800rpm・車速 16〜29km/h に集中する。**クラッチを切って
回転を合わせている最中**の値が、たまたま別の段の窓に入る。クラッチを切って惰性で転がす
だけなら回転がアイドルへ落ち、比が −30% 外れて不確定になるため誤答にならない。

### 6.5 駆動フラグを判定に用いた効果

駆動が繋がっていなければ段を答えず、繋がっていれば窓を外して最近傍で答える、という
規則に置き換えた。

![Fig8](fig9-gate.svg)

**Fig8. 駆動状態ゲートの効果。** 駆動中に段が付いた割合が 87〜96% から 99% 台へ上がり、
駆動していないのに段を答えた行が 0 になった。

窓を外したぶんが丸ごと回復している。棄却されていた点の多くは変速過渡であり、駆動中と
分かっていれば段そのものは最近傍で決まるためである。**誤答を弾く役を駆動フラグが担うので、
窓は「どの段か」を決める本来の役目に専念できる。**

### 6.6 この改善は ELM327 経路には及ばない

§1.2 で述べたとおり、標準層と独自層はセッションとして排他である。したがって
**ELM327 を用いる経路には駆動フラグが来ない。** 走行中モニタの判定は比推定のままで
ある。

ただし、前編側に何も還元されないわけではない。**判定則の案を、手作業のラベルに頼らず
評価できるようになった**ことが本質的な成果である。過学習を検出できない状態から脱した。

## 7. 考察

**手順の一般性。** 本プロジェクトの順序——標準層で足場を作り、独自層で真値を得て、
標準層由来の推定則を評価する——は、特定の車種や機構に依存しない。標準層は「参照信号が
既知であること」を、独自層は「推定と独立な観測が得られること」を担っており、この役割
分担はプロトコルが CAN であっても成り立つ。

**足場を先に固めることの効果。** §2.1 のとおり、未知の層へ入る前に標準層を読んで
期待値と一致することを確認した。これにより、以降に観測される不一致を「ファームウェアの
不具合」ではなく「車両側の未知」として扱えるようになる。切り分けの足場を持たずに未知の
層へ入ると、どちらの問題かを判定できない。

**構造が意味を教える場面があった。** §4.2 の「生 A/D 値 ＋ 換算値」の対は、相互相関と
桁上がりという 2 つの統計量だけで、意味を知る前に分離できた。**対になっているのは
アナログセンサだけ**であり、噴射時間のような計算値には生 A/D が存在しない。この構造上の
必然が、`18-19` を対と誤読する筋を閉じた。

**排他性が設計に課す制約。** 標準層と独自層を同時に読めないことは、単なる不便では
なく設計上の分岐点である。走行中のリアルタイム表示を市販ドングルで行う限り、駆動
フラグは使えない。逆に基板を用いれば駆動フラグは使えるが、その間 ELM327 は接続でき
ない。本プロジェクトでは、走行中の道具を ELM327 経路に、解析用の機材を基板に、と
役割を分けて解決した。

**先行事例との関係。** 独自層のフレーム構造とウェイクアップ手順については先行事例が
存在する。本レポートはそれを出発点としたが、MC52 で実際に応答するテーブルの集合は
先行事例と異なり、バイト配置の妥当性も個別に検証した。**先行事例からの推定と、MC52 での
実測を区別して記述している。** 受領した全フレームを自前で検算し、一部は採用しなかった。
情報の取得経路と参照範囲の限定は [`../firmware/PROVENANCE.md`](../firmware/PROVENANCE.md)
に記録した。

## 8. 制約・未解決事項

**噴射時間の絶対量が未確定である。** LSB は `1/256 ms` と推定したが、燃料の絶対量には
`噴射回数 × インジェクタ流量` の積が要る。現状は `nQ` ≈ 220〜330 cc/min（±20%）まで。
決め方は 2 つある。**1 速全開でレブまで回す**と定格点の BSFC から `nQ` が直に出る
（全開では無効噴射時間がパルスの 1 割しか効かないため、その不確かさに強い）。
**満タン区間の回帰**は、燃料 = `a·S − b·N` が線形であることを使い、区間を数本ためると
`nQ` と無効噴射時間が同時に決まる。

**走行抵抗の係数は仮定のままである。** ただし独自層により実測の経路が開いた。噴射が 0 の
区間はエンジンが純粋な制動要素になるため、駆動フラグと組み合わせると 2 種類のコースト
ダウンを切り分けられる。

| 条件 | 減速に効いている力 |
|---|---|
| 駆動フラグ `01`（クラッチ切り）の惰行 | 空気抵抗 ＋ 転がり抵抗のみ |
| 噴射 = 0 かつ駆動フラグ `00` | 空気 ＋ 転がり ＋ エンジンブレーキ |
| **差** | **エンジンブレーキ** |

**要るのは 60km/h 以上からクラッチを切ったまま数十秒落とす長い惰行**であり、手元の
走行には燃料カットが 167 サンプル含まれるが市街地で減速区間が短く足りない。

**未同定のフィールドが残る。** `0xD1` の index 5 / 6 / 7（未踏の条件が残る）、
同 index 8 の bit 2 / bit 3（推定 93〜95%）、`0x11` の `[7]` のスケールと一次性、
`[21]` / `[22-23]` の意味、テーブル `0x20` と `0xD0` の中身。

**`0x20` / `0xD0` は手元のデータでは解けない。** 231 フレームあるが 229 が停車探索
由来で、既知信号との相関は全部 |r| < 0.35 である。速度も負荷も振れていないため、
走行中の専用ポーリングが要る。

**誤答率の交絡が解けていない。** 3 本で 3 倍動くことは示したが、走行内容のどの要素が
効いているかを分離していない。

**本レポートの数値は 1 個体・1 台の基板によるものである。**

## 9. まとめ

Honda CB250R（2BK-MC52）のメーカー独自層について、以下を同定した。

1. 規格と一致するのは **OSI 第 1 層だけ**である。第 2 層以上はすべて規格外であり、
   市販のドングルでは到達できない。同じ理由で標準層とは排他になる。
2. 実在するテーブルは **7 本**。応答チェックサムは総和の 2 の補数で 256/256 一致。
   keep-alive は不要である。
3. `0x11` のアナログセンサは**「生の A/D 値 ＋ 換算値」の対**で並ぶ。この構造は
   相互相関と桁上がりだけで、意味を知る前に分離できる。
4. **噴射時間**を同定した。標準層に対応する量が無い。LSB は `1/256 ms` と推定した。
5. `0xD1` index 4 が**駆動の断続**、index 9 が**ラジエータファン**を示す。
6. **ギヤ段そのものは存在しない。** 前編の比推定に代わる手段は、この車の診断層には無い。
7. 駆動の断続を真値ラベルとして用いることで、前編の推定則の誤答を機械的に計数できる。
   誤答率は走行内容により **4.2%〜12.1%** と 3 倍動くため、率ではなく生成機構で語るべき
   である。
8. 誤答の低速側は、**正しい項が正しい理由で低速域を通しすぎている**ことに起因する。
   窓の調整では解消できない。

標準層で足場を作り、独自層で真値を得て、推定則を評価する、という順序は車種に依存
しない。K-Line を用いる他の二輪車、および CAN を用いる車両の未文書化診断データにも
適用できる。
